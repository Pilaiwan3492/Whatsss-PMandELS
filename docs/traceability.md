## 6. Documentation Review Checklist (Future PRs)

Before merging any future feature or release PR, verify:
1. **Requirements & Scope:** Any new/modified `FR`, `BR`, or `NFR` has explicit approval recorded in §5 Requirements Change Log; unapproved proposals are marked `Proposal Pending Approval`.
2. **Traceability & Exact Test Names:** `docs/traceability.md` links `Req → Feature → Sprint → AC → Planned Test ID → Actual Test File → Exact it(...) Name → Result → Tested SHA`.
3. **SHA & CI Separation:** Tested code/release SHA, CI Run URL, and documentation-sync commit SHA are cleanly separated; never self-reference an uncreated commit SHA.
4. **API & Ordering Consistency:** Query parameters (e.g., `startDate`/`endDate`), response schemas, and sort orders (e.g., `sequence_number DESC` newest-first) match source code across SRS, SDS, contracts, and STS.
5. **Deployment & Recovery Honesty:** Cloud Run revision, image digest, URL, and backup/recovery status reflect only verified execution evidence.
6. **Cross-Document & PDF Sync:** All affected `docs/*.md` files and regenerated PDFs match before final merge.
